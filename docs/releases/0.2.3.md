Candy 0.2.3 fixes the malware warning macOS shows for a freshly downloaded copy.

## What's changed

- The app binary no longer carries rpaths that exist only on the machine that
  builds Candy (`Xcode.app` and the Metal toolchain cryptex). macOS reads a load
  command path it cannot resolve as an unverifiable app, and reports a downloaded
  copy as *“Candy” Not Opened — Apple could not verify “Candy” is free of malware
  that may harm your Mac or compromise your privacy.* on its first launch, even
  though the signature is notarized. `scripts/build-app.sh` now drops every rpath
  outside the system libraries and the bundle itself before signing, and
  `scripts/release.sh` refuses to package a binary that still has one.
- Nothing else changed: every tool, shortcut and format behaves as in 0.2.2.

## Install or update

Requires **Apple Silicon and macOS 14 (Sonoma) or later**.

```sh
brew install --cask rath/tap/candy
```

For an existing installation, quit Candy and run:

```sh
brew update && brew upgrade --cask candy
```

Or download `Candy-0.2.3-macos-arm64.zip`, unzip it, and drag `Candy.app` to
Applications. The app and bundled CLI are signed with Developer ID and notarized
by Apple.
